## Purpose

へるすぴあ、コナミスポーツクラブ、コナミ提携施設、およびセントラル系列の掲載を契約経路ごとに保持し、地図と一覧が週次で確認された施設情報とITS補助適用後の都度利用料金を利用できるようにする。

## ADDED Requirements

### Requirement: ジム情報の保持

システムは、各ITS補助対象ジムの掲載について、掲載を識別する情報、名称、ブランド、契約経路、住所、位置情報、およびITS補助適用後の1回あたりの都度利用料金を保持しなければならない（SHALL）。契約経路は、へるすぴあ、コナミスポーツクラブ、コナミ提携施設、またはセントラル系列のいずれかとして識別できなければならない（MUST）。料金は日本円の金額として扱わなければならない（MUST）。

#### Scenario: ジム情報を地図へ提供する

- **WHEN** 地図と一覧が対象ジムの情報を取得する
- **THEN** 各ジム掲載の名称、ブランド、契約経路、住所、位置情報、およびITS補助適用後の都度利用料金が提供される

### Requirement: 契約経路ごとのレコード管理

システムは、掲載元と契約経路が異なるジム情報を独立したレコードとして管理しなければならない（SHALL）。名称、住所、または位置情報が一致しても、異なる契約経路のレコードを同一施設へ統合してはならない（MUST）。

#### Scenario: 同一施設が複数の掲載元に存在する

- **WHEN** 同じ物理施設がコナミ提携施設とセントラル系列の両方に掲載されている
- **THEN** それぞれが独立したレコードとして公開用データに含まれる
- **AND** 各レコードが自身の契約経路とITS補助適用後の都度利用料金を持つ

### Requirement: 情報の出典と確認日

システムは、各ジム掲載について、ITSの利用資格および補助料金の根拠となる参照先と、施設運営者または掲載元が公開する施設情報の参照先を保持しなければならない（SHALL）。同じ参照先が両方の根拠を満たす場合は、1つの参照先を使用できる。システムは、必要なすべての参照先について内容を最後に確認した日を保持しなければならない（SHALL）。

#### Scenario: 公開するジム情報を確認する

- **WHEN** ジム情報が公開用データに含まれる
- **THEN** その掲載にITSの利用資格および補助料金の根拠となる参照先が含まれる
- **AND** 施設情報の根拠となる参照先が含まれる
- **AND** 必要なすべての参照先の最終確認日が含まれる

### Requirement: AIを使用しない決定論的なカタログ生成

システムは、公式情報の取得、施設情報の抽出、分類、正規化、料金変換、および公開用データの生成を、スクレイピングと明示的な変換規則による再現可能な処理で行わなければならない（SHALL）。カタログの作成および更新処理は、AIモデルまたはAIサービスを使用してはならない（MUST）。公式情報の構造または値を既知の規則で処理できない場合、推測で補完してはならず、更新を失敗させなければならない（MUST）。

#### Scenario: 公式情報からカタログを生成する

- **WHEN** カタログの作成または週次更新を実行する
- **THEN** 固定された抽出規則と明示的な対応表により公開用データが生成される
- **AND** データの抽出、分類、正規化、料金変換にAIモデルまたはAIサービスが使用されない

#### Scenario: 未知の構造または値を検出する

- **WHEN** 公式情報に既知の抽出規則または変換規則で処理できない構造または値がある
- **THEN** 推測によるデータ補完は行われない
- **AND** カタログ更新が失敗する

### Requirement: 座標化失敗の記録と明示的な補正

システムは、自動で座標化できないジム掲載を黙って公開対象から除外してはならない（MUST）。座標化できない掲載がある場合、施設名、契約経路、元住所、施設情報の参照先、および候補を採用できなかった理由を含む非公開の失敗レポートを生成しなければならない（SHALL）。人手で補正する場合は、表示用の元住所を変更せず、検索用の補正住所または確定座標、根拠URL、確認日、および補正理由をバージョン管理された補正台帳へ記録し、以後の生成で決定論的に適用しなければならない（SHALL）。

#### Scenario: 自動座標化に失敗する

- **WHEN** 公式座標、補正台帳、座標キャッシュ、国土地理院API、およびNominatimのいずれからも検証済み座標を得られない
- **THEN** 失敗レポートに該当掲載の施設名、契約経路、元住所、施設情報の参照先、および候補を採用できなかった理由が含まれる
- **AND** 該当掲載を除外したカタログは公開されない
- **AND** カタログ更新が失敗する

#### Scenario: 根拠付き補正を適用する

- **WHEN** 公式情報との人手照合により検索用の補正住所または確定座標を登録する
- **THEN** 補正台帳に根拠URL、確認日、および補正理由が保存される
- **AND** 公開用データには提供元の元住所が表示される
- **AND** 次回以降の生成で同じ補正が機械的に再現される

### Requirement: 週次での情報確認と更新

システムは、公開中のジム情報を少なくとも7日ごとに、対応するITSの制度情報および施設運営者または掲載元の施設情報と照合し、変更がある場合は公開用データを更新しなければならない（SHALL）。変更がない場合も、確認できた各参照先の最終確認日を更新しなければならない（SHALL）。

#### Scenario: 公式情報に変更がある

- **WHEN** 週次確認でいずれかの参照先との差分が見つかる
- **THEN** 公開用データが公式情報に合わせて更新される
- **AND** 確認できた参照先の最終確認日が更新される

#### Scenario: 公式情報に変更がない

- **WHEN** 週次確認で各参照先との差分がない
- **THEN** 公開用データの内容は維持される
- **AND** 確認できた各参照先の最終確認日が更新される

### Requirement: 更新失敗時の正常データ維持

システムは、公式情報の取得、検証、または更新に失敗した場合、不完全なデータで公開中の正常なデータを置き換えてはならない（MUST）。

#### Scenario: 週次更新に失敗する

- **WHEN** 公式情報の取得、検証、または更新処理が完了しない
- **THEN** 直前の正常な公開用データが維持される
- **AND** 最終確認日は更新されない
